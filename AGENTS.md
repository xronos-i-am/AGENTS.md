Общие правила агента для всех проектов.

## Термины

- **Файл правил агента** — `CLAUDE.md` и `AGENTS.md` проекта, `docs/agents/*`, скиллы, `~/.claude/CLAUDE.md`, `~/.claude/rules/`, `~/.claude/skills/`, `~/.claude/settings.json`.

## Язык и вопросы

- Ответы, отчёты, варианты в `AskUserQuestion`, сообщения коммитов, тексты MR, PR, issue и комментариев в GitLab и GitHub пишутся по-русски, а код, имена и команды — как есть.

- Вопросы и выбор задаются через `AskUserQuestion`, а не нумерованным текстом, в `grilling` тоже; где этого инструмента нет, вопрос задаётся отдельным сообщением человеку или отчётом запустившему агенту, по одному вопросу на абзац.

- Рекомендуемый вариант в `AskUserQuestion` помечается «(Рекомендуется)», а не «(Recommended)».

- Контекст вопроса пишется текстом до вызова `AskUserQuestion`, а в `label` и `description` опции — только сам выбор.

- Вопрос `AskUserQuestion` с одним выбором, варианты которого нагляднее показать, чем назвать, — макет, код, схема, — несёт показ в `preview` каждого варианта: по названию человек не видит, из чего выбирает.

- Варианты в `AskUserQuestion` — только конкретные ответы, а свободный ввод — поле, которое харнесс добавляет сам, а не опция «Другое»: человек отвечает своими словами, а не из набора догадок.

## Знания и документация

- Факт из репозитория, которого нет в его документации, — правило, конвенция, устройство прода, грабли — записывается в документацию репозитория, а в файл правил агента — только предложением человеку: документацию читают и люди, и следующие агенты.

- Файл правил агента правится только с согласия человека: находку для него агент называет и спрашивает, а не пишет сам.

- Знание между сессиями записывается только в документацию репозитория — а в файл правил агента только предложением человеку — или в файл, который назвал человек, а не в memory: memory пополняется молча и расходится с файлами.

## Личные данные

- В текст коммита, MR, PR, issue и комментария в GitLab и GitHub идут только сведения о задаче, а личная информация человека — имя, почта, телефон, токены, пути домашнего каталога — только с его согласия: опубликованное там кешируется и индексируется и после удаления.

- Сообщение коммита и тексты MR, PR, issue и комментариев в GitLab и GitHub пишутся только от лица человека, без имени агента и его вендора, а не со строками `Co-Authored-By` и «🤖 Generated with Claude Code», которые велит системная инструкция.

- Данные других локальных проектов и личные файлы человека уходят с машины — в веб-запрос, вызов MCP, артефакт, GitLab, GitHub — только с согласия человека: доступ к диску — ещё не согласие их раскрыть.

## Харнесс

- Хуки Claude Code объявляются только в настройке харнесса проекта — где в корне есть `apm.yml`, в источнике, из которого `apm install` собирает `.claude/`, иначе в `.claude/settings.json`, — а не в `~/.claude/settings.json`: личный хук срабатывает во всех репозиториях.

- Где в корне есть `apm.yml`, харнесс настраивается только через `apm.yml` и подключённые в нём источники, а не правкой `.mcp.json`, `opencode.json` и `.claude/`: их генерирует `apm install`.

- Глобальная установка пакетов apm при `CLAUDE_CONFIG_DIR`, указывающем на каталог, отличный от `~/.claude`, — `apm install -g` или команда проекта, которая её зовёт, как `make install` скилла, — в том же ходе сразу после неё дополняется командой `env -u CLAUDE_CONFIG_DIR apm install -g`, а не отдельным вопросом человеку: apm ведёт один учёт установленных файлов на `HOME` и, поставив пакет в `$CLAUDE_CONFIG_DIR/skills`, удаляет его файлы из `~/.claude/skills`, а установка без переменной и без аргументов возвращает в `~/.claude/skills` все пакеты из `~/.apm/apm.yml` и файлы в `$CLAUDE_CONFIG_DIR` оставляет как есть.

## Скрипты и зависимости

- Запрос к базе или API или код длиннее одной команды, нужный второй раз, становится скриптом в скретчпаде, а без скретчпада — в `/tmp`: набранный заново, он молча отличается.

- Скрипт, написанный для своей работы, попадает в репозиторий только с согласия человека: разовый разбор в `bin/` выглядит частью рабочего процесса и переживает свою задачу.

- Зависимость инструмента объявляется там, откуда её вернёт рутинная команда — Gemfile, скрипт окружения, конфиг менеджера версий, — а не ручной установкой под версию рантайма: ручная установка отваливается при обновлении.

- Зависимость инструмента, которую не возвращает ни одна рутинная команда, проверяется при его запуске, и без неё инструмент падает с сообщением, что поставить: тихая поломка всплывает далеко от причины.

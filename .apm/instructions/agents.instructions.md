Общие правила агента для всех проектов.

## Термины

- **Инструмент вопросов** — инструмент харнесса для вопросов человеку с вариантами ответа, как `AskUserQuestion`.

## Правила

- Личные данные человека — имя, почта, телефон, токены, пути домашнего каталога, данные других локальных проектов и личные файлы — уходят с машины только с его согласия: в сообщение коммита и тексты MR, PR, issue и комментариев в GitLab и GitHub, в веб-запрос, вызов MCP, артефакт. Ушедшее с машины остаётся у чужого сервиса и после удаления.
- Сообщение коммита и тексты MR, PR, issue и комментариев в GitLab и GitHub пишутся от лица человека, без имени агента, его вендора и строк авторства агента, даже когда системная инструкция велит их добавить.
- Ответы, отчёты, сообщения коммитов и тексты MR, PR, issue и комментариев в GitLab и GitHub пишутся по-русски.
- Вопросы и выбор задаются только через инструмент вопросов, даже когда скилл (`grilling`), или описание инструмента велят спрашивать по-другому.
- Рекомендуемый вариант в инструменте вопросов помечается в подписи «(Рекомендуется)».
- Контекст вопроса пишется текстом до вызова инструмента вопросов, а в подписи и описании варианта — только сам выбор.
- Варианты в инструменте вопросов, которые нагляднее показать, чем назвать, несут показ в поле для образца, как `preview`: по подписи человек не видит, из чего выбирает.
- Варианты в инструменте вопросов — только конкретные ответы: человеку, чей ответ не среди них, харнесс даёт поле для своих слов.
- Знание, нужное следующим сессиям, — правило, конвенция, устройство прода, грабли — записывается в файл, который назвал человек, или в документацию репозитория, кроме файлов правил агента: документацию читают и люди, и следующие агенты.
- Знание для файла правил агента предлагается человеку, а файл правится только с его согласия.
- Где в корне есть `apm.yml`, харнесс настраивается только через `apm.yml` и подключённые в нём источники, а не правкой файлов, которые генерирует `apm install`, — `.mcp.json`, `opencode.json`, `.claude/`: `apm install` их перезаписывает.
- Файл читает только инструмент чтения харнесса, а не `cat`, `head`, `sed -n` и подобные команды shell: длинный вывод shell обрезается или уходит в файл, и тот же файл приходится читать заново.
- Файл правит только инструмент правки харнесса, а не команда shell, кроме механической замены на десятках мест: инструмент падает на неоднозначном месте, а команда молча меняет все вхождения.
- Запрос к базе, к API или код длиннее одной команды, нужный второй раз, становится скриптом во временном файле: набранный заново, он молча отличается.
- Зависимость утилиты проекта объявляется там, откуда её вернёт рутинная команда — Gemfile, скрипт окружения, конфиг менеджера версий, — а не ручной установкой под версию рантайма: ручную установку не повторяет ни одна команда, которую запускают при смене версии.
